# CCPG 方案插件安装

把安装 ZIP 保存到电脑，在 DSH 会话中说：

> 请帮我安装这个 CCPG 方案插件包。按包里的安装说明执行，安装到我当前使用的 DSH 环境，保留我的会话、插件、材料和成果。

安装完成后完全退出并重新打开 DSH Desktop。配置自己的模型，登录自己的飞书账号，就可以在会话中提出方案需求。

交付包只带运行所需的聚合插件、章节技能及参考资源、侧栏依赖和安装入口。历史开发文档、测试、旧的拆分插件、品牌插件和用户材料不在包内。原有 harness-one 功能仍包含在聚合插件中。

## 给负责安装的智能体

- 用户提出安装请求即授权安装本包及必要依赖。不需要源码或本机全局技能，不使用公共 `npm latest` 代替内部包。
- 先解压到用户可读写的目录。ZIP 中有标准 npm 插件 `.tgz`、固定版本 sidebar `.tgz`、`delivery.json` 和零外部依赖的 `install.mjs`。
- 使用当前宿主提供的 Node 和 DSH。官方 Desktop 的 **Open DSH Terminal** 已提供这些运行时。不要安装系统 Office、OCR、原生 canvas、Homebrew 或编译工具。
- 确认当前会话所属 profile；优先使用宿主提供的 profile 信息/环境。不要从目录列表猜选，不默认创建 `dsh-ccpg`。仅当确实无法识别时，指导用户在 **Open DSH Terminal** 执行以下命令。
- 先用 `node "/解压目录/install.mjs" --profile "当前profile" --check` 检查包摘要、Node、DSH 和已有 profile。Desktop 托管终端可在当前 profile 目录运行，省略 `--profile`。
- 再执行同一命令去掉 `--check`。Windows PowerShell 也使用相同 Node 命令；无需 sh、WSL 或 Git Bash。
- 安装器调用官方 `dsh plugin --profile ... add` 安装两个固定归档，关闭生命周期脚本和 peer 自动安装，保留官方兼容/包操作门禁。新增 SDK 副本、放宽版本豁免、修改宿主/端口/模型、删除旧插件均不允许。
- 两个包的直接 bundle 注册和内部版本检查通过后，安装器检查 PDF WASM、Word 图片导出及全部章节技能。成功会返回 `installed: true`；发生错误不得声称安装完成或循环重试相同错误。
- 需要联网下载纯 JS/WASM 依赖；这不是完全离线包。下载失败应报告依赖下载失败，不要求业务用户排查源码。
- 不自动退出用户正在运行的会话。安装成功后提示用户完整重启 Desktop；生成途中应先保存并停止任务。
- 飞书 CLI 使用当前用户/当前 profile 的登录机制；用户自行完成授权。CCPG CLI 是按项目需要使用的外部业务工具，不是插件启动的前置条件。
- 旧的七/八个独立包混装会在安装前阻止操作。保留旧插件和数据，交由运维迁移，不擅自删除。

## 支持边界

内部包面向 macOS、Windows、Linux 的 x64/arm64，Node >=22.19，DSH >=0.2.0-rc.2 且 <0.3.0。标准 Cordis 入口、bundle patch 和原生 Web Client 不变；未知主版本拒绝安装，不能声称任意历史版本兼容。

PDF 引擎及图像转换使用随依赖分发的 WASM；Office 结构读取、Excel 与 Word 输出使用 JavaScript。普通文档优先提取，扫描/复杂内容使用配置好的原生多模态能力，整件保留并按需核对。旧 DOC/PPT 无可靠提取时登记为待文档核对，不假装解析成功，不安装系统 Office 转换器；若宿主/模型无法读取，应明确请求等价可读原件。

跨平台设计和自动检查不等于每个平台真实 Desktop 已验收。首次向同事推广前应完成目标操作系统试点；本包不包含账号凭据或用户项目材料。
