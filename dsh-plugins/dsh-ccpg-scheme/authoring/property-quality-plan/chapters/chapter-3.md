## 3 项目与顾客分析

按 `3.1 → 3.2 → 3.3 → 3.4` 组织本章。3.3 承接 3.1、3.2，3.4 承接前三项。材料是否可用以当前项目索引为准，输入编码是材料角色，不是指定文件名。

### 3.1 项目基本概况

- 使用随附的四份模板，分别形成项目基本信息、空间资源信息、设备设施信息、管理用房/设备房/重点部位清单；保持每份模板的模块、表头、字段顺序和固定项目。
- 基本信息保留“项目基本信息、项目区位及周边环境、项目业态构成、项目历史沿革”四模块；区分占地、建筑、服务及收费面积，区分建设、验收、交付和服务进场时间。
- 只使用已确认的时间粒度，不补造日期；分期、相邻和同名项目的地址、户数、面积、车位分别核验。
- 空间资源保留“空间资源信息、楼栋/户型及入住情况、出入口及交通组织、停车资源及公共空间”四模块。
- 空间资源表按“空间类别、数量/面积、用途、分布、使用状态”；楼栋表按“楼栋、户型/面积区间、套数、建筑面积区间、主要分布楼栋、空间材质类型、备注”填写，最终以随附模板字段为准。
- 出入口按类型、数量、位置、使用对象、材质和备注整理；停车资源区分总量与地上/地下、固定/临时/访客等分类；公共空间记录位置、规模、可支持活动及可用时间。
- 不将总户数或总车位数平均分配到楼栋或分类，不根据空间名称推断材质、运营状态或管理权属；模板已有“其他”承载项时在其内归集经证实对象。
- 设备设施按模板的工程、秩序、园艺、保洁、多种经营资源模块整理；系统返回空数据不能直接证明没有资源。
- 读取资源工作簿的相关工作表及实际表头，保留空间层级路径，空白末级不丢记录；区分空间名称与资源名称、物理资源属性与经营属性。
- 以有效资源编码识别重复，缺编码时结合区域、空间路径和名称核对；复合条线资源可用于多个专业，但项目总量不得重复累计。
- 管理用房、设备房、重点部位分别成表，核对用途、位置、状态、设备、维保及责任岗位；合同总面积不可直接拆为房间面积。
- 同一指标复用经核实的口径，校验分类与合计。差异按期间、单位、范围和证据核对，不靠平均或调整数值凑平，也不采用固定来源优先级。
- 合同中的历史户数、面积、设备和费用仅作其适用期间依据；服务期限与补充协议关系在运行时核对。
- 如需补充区位和公共配套，可查询匹配项目实体的公开权威信息并保留日期、定位和采用依据；公开介绍不证明服务边界、权属或当前运营状态。

### 3.2 顾客特征分析

- 依据当前项目客户基础资料和有效标签，分析客户结构、居住状态、业态及客群规模；不从案例推断客户身份或比例。
- 多种经营资料区分商铺物理资源与签约、业务状态等经营属性，资源总量与 3.1 一致。
- 从重要相关方资料识别职责、诉求、影响和沟通重点；个人信息按业务需要最小化，内部主体使用岗位。
- 从可用投诉、报修记录按类别、区域、期间及处理结果识别需求；费用资料区分预缴、应收、收缴率及各自期间，满意度材料用于校准结论。
- 按顾客特征模板输出结论性描述，数值和占比须有数据依据。可选资料未提供不阻塞其他可完成内容。

### 3.3 项目特点分析

- 承接 3.1、3.2，综合有效合同约束、承接背景、建设移交遗留问题、设施空间特征及运行表现，形成对管理有实际影响的特点。
- 区分标准作业事项与已执行任务；按有效主键或经核对的条线、地点、事项和期间关联，不按行号匹配，不把计划视作执行成绩。
- 品质资料按检查计划、检查工单、不合格整改单关联，计划不计入问题数；同一问题不重复统计，整改中或仅填对策不视作已验收关闭。
- 识别反复故障、维护偏差、高频投诉、重复不合格和闭环薄弱环节。筛选对应专业，无法可靠归类的记录不硬归类。
- 本项输出特点结论；挑战、原因、措施和衡量指标留给 3.4，避免重复。

### 3.4 关键挑战及成功因素描述

- 每条挑战对应 3.1 至 3.3 的具体事实，按模板呈现“关键挑战、形成原因、成功因素、应对措施、衡量指标”。
- 原因简要说明困难，措施对应挑战，指标可验证；条目数量按事实确定，不凑齐案例维度。
- 地域、气候、材质、设施和服务事项根据当前项目适配；不强制加入某一城市的气候、历史合同差异或特定设施风险。

### 交付

- 四个输出均为正文，使用各自模板及随附参考案例的表达粒度；案例仅供写法参考。
- 保留模板结构。必要事实无法确认时进入独立确认记录；需要该事实才能完成的成果不得伪装为最终稿。
- 正文不混入材料编码、下载路径、源表坐标、推导过程、冲突处置和内部个人资料。
