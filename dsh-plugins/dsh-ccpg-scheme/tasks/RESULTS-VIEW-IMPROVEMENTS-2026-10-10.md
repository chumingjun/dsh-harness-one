# 方案成果页优化补充

日期：2026-10-10。最新状态：插件优先、浏览器暂缓。成果展示已修复并装配本地安装包；真实 Desktop 已打开面板，窄容器布局问题已补修。用户方案数据保持只读。下方调查为修改前基线。

## 用户反馈与已核实事实

用户截图显示目录连续编号为 1 至 15，与业务章节结构不一致；材料、依赖等区域缺少业务定义中的内容。用户希望同一成果也可以在本机浏览器中查看。

- `src/client.jsx` 使用 `row.order` 展示编号。当前 manifest 已有业务 `code`，其中 8.1 至 8.5 的执行 order 是 8 至 12，后续第 9 至 11 章的 order 是 13 至 15。执行顺序正确不代表目录编号正确。
- 当前 `ListsPanel` 仅列全局已登记材料、当前章的前置章节 ID，以及已产出成果的证据/附件/确认项；未展示当前章的 `inputs`、`outputs`、`references` 和材料绑定状态。
- r2 默认包有 15 章、417 份资源。第 3 章定义 41 项输入、第 4 章定义 10 项输入，章节 `references` 包含知识、输出模板、参考案例及采集模板。页面空白不能作为这些定义或原件未打包的证据。
- 部分章节的结构化输入数为 0，部分资源仅下载且仍是 `needs-vision`，一项保洁参考案例按用户授权跳过。必须分别核对业务定义和实际可用状态，不能宣称所有依赖已就绪。
- 当前只有原生成果面板及 `/ccpg-scheme/api` 数据接口，没有已交付的独立浏览器成果页；数据接口不是给业务用户的网页地址。

调查依据：用户截图、当前源码、`rules/manifest.json` 与已有 revision 8073 来源快照；本轮不重新读取整份飞书业务表。

## 后续调整范围

1. **目录对应业务定义。** 使用已存在的 `chapter.code` 和标题展示编号；`order` 只用于执行与排序。按固定业务快照核对父章节、子章节及章内输出项；不能解析标题猜层级，也不能把没有执行内容的父节点变成新执行章节。
2. **同时显示要求和完成情况。** 按当前章显示输入名称、必填/可选/待确认、已绑定材料、解析状态及缺口；章间依赖显示业务编号、标题和实际成果状态。未提供材料、尚未生成、定义缺失、待视觉核验和权限跳过要分别说明。
3. **展示技能自带资源。** 复用 `references` 的角色、正文/原件路径和 `inputIds`，展示知识、模板、案例和采集模板；复用 `outputs` 展示正文、附件及章内依赖。不复制另一份规则。「本章输入」仅放项目材料和数据；知识角色的关联项只放在「知识依赖」，包括尚未下载或解析的知识，保留真实状态。空白模板不能充当项目事实。
4. **增加本机浏览器查看入口。** 复用当前 DSH Host、成果组件和已落盘数据，首步提供只读浏览器成果页及简单的“在浏览器查看”入口。使用 Host 实际地址和端口、当前方案及会话关联，不写死测试端口或开发机路径。

保持会话执行、页面成果展示的分工。浏览器入口不新增生成/继续/暂停/中断按钮，不另建后台、项目列表或模型循环。插件面板中的编辑与确认继续使用原生人工操作通道；不能因增加浏览器查看而把人工操作降为普通 HTTP 写入。

## 浏览器入口边界

- 沿用 DSH 原生浏览器认证、loopback 与目录边界；知道项目 ID、会话 ID 或链接不能替代认证。不得通过移除 `connection.admit` 使页面可用。
- 先验证普通浏览器如何完成原生认证与会话定位，再决定最终 URL 和打开方式；目前不向用户提供虚构地址。
- 本地页面需 DSH 正在运行，仅服务当前设备。对其他人的交付仍使用经用户确认的飞书文档或导出文件，不自动暴露局域网/公网服务。
