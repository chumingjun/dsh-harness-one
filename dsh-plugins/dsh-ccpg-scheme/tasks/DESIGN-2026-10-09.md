# CCPG Scheme DSH 插件整体设计确认稿

日期：2026-10-09。状态：产品方向与架构复核意见已获用户确认，用户随后授权在独立主干分支完整开发并按 TDD 推进。具体实施与未完成项见 [IMPLEMENTATION-PLAN.md](IMPLEMENTATION-PLAN.md)，接入与验证见 [TECHNICAL-ARCHITECTURE.md](TECHNICAL-ARCHITECTURE.md)。

开发侧记录统一入口：[PROCESS.md](PROCESS.md)；开发规则见 [插件开发 AGENTS.md](../AGENTS.md)。本文中的方案目录 AGENTS.md 是运行产物，两者不能混用。

## 1. 目标与边界

首版做一个 DSH Desktop 本地单用户插件，随 `dsh-harness-one` 内部聚合包一次安装。插件提供专用方案工作目录初始化、材料入口、章节执行状态、成果展示/编辑、断点继续、Markdown 导出和飞书发布；模型执行、上下文管理、文件读取和会话交互使用 DSH 原生能力。不迁移旧平台服务端，不做多人共享服务，不建第二套聊天系统，不做企业管理后台。

旧章节 JSON 和旧 Skill 仅作参考，不作为规则 authority。规则以业务梳理表、模板原文、知识原文、项目材料和经实测的 CCPG CLI 能力为准。旧平台规范化材料只用于首轮本地测试，不进入通用安装包。

## 2. 专用方案工作目录

首次使用时，用户显式创建或选择一个空目录（或已有方案目录）。插件初始化后，该目录成为后续 DSH 原生会话 cwd。若当前会话 cwd 不是已初始化方案目录，页面提示初始化/切换，不写外层仓库。

推荐结构：

```text
<scheme-workspace>/
  AGENTS.md                     稳定入口规则，不追加动态过程
  .dsh/skills/                  项目级章节 Skills
  materials/
    raw/                        用户原始材料，保留原样
    fetched/                    CCPG CLI / 飞书 CLI 来源快照与获取元数据
    parsed/<source-version>/    材料/知识原文转出的 Markdown、图片及来源定位
    notes/                      按需生成的材料总结/提炼笔记
  outputs/
    chapters/<chapter>/<artifact>/
      body.md                   章节正文
      summary.md                下游优先读取的章节总结
      attachments/              独立附件
      evidence.json             事实与来源映射
      confirmations.json        确认项
      context-refs.json         本章用到的材料/上游精确引用
    final/<version>/            全案 Markdown 与附件
  .ccpg-scheme/
    workspace.json              工作区与规则版本标识
    state.json                  小型章节状态与最新成果指针
    index.json                  AI 可读的动态索引
    publications.json           飞书发布记录
```

## 3. AGENTS 与动态索引

`AGENTS.md` 保持稳定，只写全局规则：先读 `.ccpg-scheme/index.json`；优先读 summary/notes；需要精确事实时按 `context-refs.json` 回读原文片段；不得整读大文件；不得把示例当项目事实；输出必须提交给插件工具保存。

动态过程不追加进 `AGENTS.md`。`state.json` 是唯一可写业务状态源；插件在章节提交、编辑、确认、材料登记与提炼完成时先完整保存成果，再更新 state 指针并重建同 revision 的 `index.json`。索引只保存材料、notes、成果、依赖、确认和发布记录的小指针；滞后时据 state 重建，不把多个文件重命名当跨文件事务。workspace 保存工作区身份和格式版本，publications 保存发布回执，不形成另一个章节状态源。DSH 会话日志仍负责原生对话历史，AI 按索引通过原生文件能力读取具体内容。

这样避免两个问题：`AGENTS.md` 被执行记录撑爆；以及 AI 每次扫描整个工作目录。

## 4. 材料处理

登记保持轻量：记录原路径/复制路径、类型、大小、hash、解析状态和用户说明。相同 hash 标记重复；不做语义去重，不预建全量索引，不做自研上下文管理。

飞书文档、表格与知识材料使用当前用户已授权的 `lark-cli` 获取，记录原文快照、来源标识、获取时间、范围和可获得的远端版本；表格分页及附件要单独核对，不能把标题或 URL 当已读内容。普通本地文件仍走本地入口。只处理用户指定范围，检查软链接越界与敏感文件；材料中的指令和宏不执行，不额外上传到转换服务。使用远程模型时遵循宿主及公司数据授权，不把本地应用宣称为离线应用。

总结、归纳、提炼由章节 Skill 在需要时执行。生成后的材料 note 保存到 `materials/notes/`，包含结论、适用范围、精确来源定位（文件 hash、页码/章节/标题/表格/行号/字段）和生成时间。后续章节优先读 notes；只有需要原文事实时才按定位读取小片段。上下文大小与压缩由 DSH 原生 Agent 管理。

Office/PDF 解析是一期必需能力，覆盖用户提供的材料和章节实际依赖的知识文件，不能以后续接入为由跳过。用户无需自行转 Markdown，也无需逐个安装解析 Skill。文本/Markdown/CSV/JSON 可直接读取；PDF、Word 等 Office 文件由随插件内置的默认解析 Skills 指导 DSH 原生 Agent 调用工具、解读并转换。

默认解析流程：

1. 取得授权原文并保留原件，辨别格式、页数/工作表/幻灯片及是否扫描件。知识来源不能只留下 URL、标题或摘要；已提供的输入项逐项登记，未读取或不相关的文件说明状态，不假装已读。
2. 文字层和 Office 正文/表格可复用成熟解析工具；扫描页、图片及复杂版面直接交给用户配置的多模态模型解读。不安装传统 OCR 引擎、OCR 语言包或 OCR 服务，也不把 OCR 作为失败后的自动降级。Skill 负责指导流程，必须核实 DSH 实际可以把文件或图像传给当前模型，不能仅凭模型名称声称视觉链路可用。
   若模型接入支持直接读取 PDF，就直接传递；否则利用已有文件能力将所需页面渲染为图像，再分批交给多模态模型。页面渲染只做格式转换，不引入 OCR 识别。正文提取、页面渲染、模型解读复用现有能力，不自研解析引擎。
3. 分页、分节或按工作表处理大文件并保存进度与结果，不把整个原始二进制文件塞入文本上下文。DSH 负责上下文管理。默认先完成本次方案所需材料与知识的读取转换；摘要优先只影响后续消费，不允许以摘要替代原文解析。
4. 转换结果保存到 `materials/parsed/<source-version>/`，以 Markdown 为可读正文，必要图片和复杂表格附件一同保存。记录原文件版本、页码/标题/表格/单元格等定位、处理范围及未识别部分。逐字提取、视觉识别、模型解释与摘要应可区分，转换不能擅自总结删改数字或编造缺失内容。
5. 索引关联原件、解析结果和 notes。相同原件版本且解析结果有效时复用，不让每个章节重复转换；文件变化或解析不完整时只处理需要更新的部分。总结提炼仍单独保存在 notes，不代替完整的相关来源内容。
6. 解析后检查正文、表格、关键数字和必要图片的覆盖；扫描件关键数字结合原图复核。模糊字符、数字或单元格无法确认时保留明确待核对项，不补猜数值。加密、损坏、模型无视觉能力或 DSH 传图失败时明确原因；先尝试分批处理等已有能力，确实无法处理才请用户提供清晰原件、解锁或调整模型配置。只阻断受影响的必需输入，不以空 Markdown 或一句摘要标记成功。

默认 Skill 的最终来源和工具选型须基于真实样本验证及分发条件确定。首版验收包含文字 PDF、中文扫描 PDF、带表格/图片的 Word，以及实际材料中的 Office 格式；旧 `.doc` 等格式需验证转换链，不能暗称与 `.docx` 同等支持。验证覆盖实际章节知识原文，不能只测用户材料。

## 5. CCPG CLI

标准产品名 CCPG CLI，命令 `ccpg-cli`。本机 1.2.16 只是实测版本，不是兼容范围承诺。

策略：能力已经项目级验证时优先自动获取；能力不存在、无权限、字段/期间/口径不匹配或查询失败时，明确转为用户补材料。查询结果和查询元数据保存到 `materials/fetched/`，按材料同样登记 hash 与来源；失败不伪装成功，不自动无限重试。

优先取数不是事实优先级：与人工材料冲突时保留双方来源、期间、单位及口径，必要时请用户确认，不静默覆盖。

## 6. 章节执行

首版不并发。规则定义依赖和自然顺序，默认严格逐章执行；当前章阻塞时不自动跳到后章。

同一方案默认复用一个 DSH 原生会话连续执行各章，不按章新建独立 Agent 上下文。每章独立保存进度与成果，材料解析、笔记及上游成果跨章复用；公共指令尽量稳定，章节任务增量追加。上下文压缩交给 DSH，模型缓存取决于服务商，不能承诺命中率。必要的原文核对允许再次读取相关片段，不能把它变成全量重新解析。

顺序机制：

1. 启用规则前校验缺失依赖、循环依赖、重复章节及与自然顺序冲突的逆序依赖；有冲突拒绝执行并说明，不由模型自行重排。
2. 按规则包显式 order/章节编码定位最前的未完成章节，不使用文件遍历或导入顺序。
3. 校验该章依赖、材料和确认条件；不满足就报告阻塞原因，不自动跳过。
4. 只有用户明确要求跳过时才允许执行无该章依赖的后续章，保留缺章标记。
5. 在同一原生会话执行、校验提交并满足必要确认后继续下一章；只显示已接纳的正式成果。

通过 Cordis 插件、原生工具 restriction/guard、执行前钩子和生命周期事件接入，不另建后台派发循环。插件业务方法仍需在最终提交时检查 attempt、版本、取消和完整性；观察事件不能替代提交事务。人工确认是绑定成果版本的真实用户操作，不能由模型自行批准。

章节内部多个输出的先后关系写在章节 Skill 中，由该章节执行时遵守；首版不把输出级依赖升级为全局并发调度。

## 7. 输出与执行记录

每次章节提交生成不可变 artifact，至少保存正文、总结、附件、证据、确认项和引用。手工编辑或 AI 修改生成新版本，不覆盖旧版。state 更新最新指针，index 据此重建。模型写候选成果，通过业务工具接纳后才成为正式版本；逐项校验正文、规定附件、来源和确认条件。若通用文件/shell 工具仍能绕过提交，读取或发布前核对外部修改并转为待接纳，不把工具 hook 宣称为操作系统级隔离。

下游章节优先读取上游 `summary.md` 和 `context-refs.json`，需要完整措辞或细节时再读取指定 artifact 的正文片段。上游修改后，插件只标记受影响下游 stale，由用户决定是否重跑。

断点续执行按章节边界：已提交成果保留；prepared/running 中断后标记 interrupted；继续时优先恢复同一原生会话并重新 prepare 未完成章节。会话不可恢复时使用已保存索引、材料和成果继续，不承诺恢复模型中间计算或原生脚本中途位置，不重新全量解析材料。

同一方案同时只有一个有效章节 attempt；停止后迟到结果不能改正式成果。原生取消信号传播到工具，恢复前检查旧执行资格。单用户双窗口仍需写入互斥、版本检查及崩溃残留占用恢复，防止重复提交和编辑覆盖，不引入并行调度。

## 8. 工作台页面

不做项目列表。首次进入是工作区初始化/选择；之后进入当前方案工作台。

页面保留旧平台中有用的成果视图风格：

- 左侧：自然顺序章节列表、依赖状态、阻塞原因。
- 主区：正文预览/编辑、附件、证据、确认项、章节总结。
- 材料区：原始材料、CCPG CLI 获取结果、notes、重复与解析状态。
- 成果操作区：直接编辑、保存、确认、引用到会话、导出 Markdown、发布飞书。

生成、继续、重跑、暂停和中断统一从 DSH 原生会话交互，不在插件页面重复开发运行按钮、刷新进度按钮、日志控制台或另一套聊天。页面以成果预览和调整为主，保留版本、未完成、待确认及上游过时等必要状态。成果提交后自动同步展示；这些本地读取不调用模型。

选中文字或表格后可将章节、版本、片段引用带入当前会话，让用户在那里提出修改要求。页面不单独派发 AI 任务，不新建 Agent；手工保存和成果确认只更新成果状态，不自动开始下一章。执行交互简化不取消依赖校验、落盘、版本冲突检测和章节边界恢复。

## 9. 飞书材料读取与发布

一期统一复用用户本地或 DSH 当前 profile 已安装并授权的官方 `lark-cli`，沿用 `dsh-ccpg-larkauth` 登录能力，显式 `--as user`；读取飞书材料、知识及发布成果使用同一明确账号。CLI 入口失败不自动切换另一安装的账号，不静默降级 bot；授权失效或权限不足时恢复授权或请用户补料，不另建认证和 API 客户端。按 D-046，用户要求创建或点击转换即为创建授权，不二次确认、不依赖模型轮次批准；覆盖已有远端文档仍保留批准。凭据留在 CLI/宿主，不进入方案目录。

本地 Markdown 是主版本。发布固定成果快照，通过 CLI 创建/更新并回读校验正文、表格和必要附件，保存目标、可获得的 revision、时间和 artifact 版本。不做双向同步；远端已变更时不静默覆盖。超时或部分成功先核对既有目标及回执，不能盲目重复创建；必需附件缺失不算完整发布。发布期间本地新编辑不改变该次快照。

## 10. 打包与更新

默认规则、Skills、展示定义和插件代码随 `dsh-harness-one` 内部聚合包分发；用户材料、运行状态、成果和凭据绝不入包。内部包标记 channel，禁止公共 npm latest 覆盖内部版本。首版没有在线升级中心，使用内部包重复安装/覆盖更新，并保护失败时旧安装可用。

默认 Skills 包含 PDF、Word/Office 读取转换能力，初始化方案目录时随章节 Skills 一起部署为项目级可用技能，并在运行 AGENTS.md 中说明调用入口。复用已有成熟技能时核验来源、许可证和实际依赖，移除开发机专用路径与传统 OCR 安装要求。必要的文件解析/页面渲染依赖纳入统一安装，图片和扫描页解读使用用户配置的多模态模型；检查实际视觉输入链路，缺项明确报告。不要求用户另找技能手工安装，也不修改用户全局 Skills。

“升级分发”仅指防止公共更新覆盖内部插件，不是复杂升级后台。

项目固定已激活规则包版本。安装升级只更新可用默认包，不自动改变旧项目；已有项目暂停后明确激活兼容新版，先校验输入输出、依赖和资源，再标记受影响成果，失败保留原版本。执行中不热替换 Skill，已完成成果不自动重算。交付使用联合验收的版本组合，不盲目升级全部 latest；卸载保留用户方案目录，不首版建设通用迁移平台。

开发侧 authoring Skill 与业务源码共同维护，用于生成候选章节 Skills、运行 AGENTS.md 和最小必要定义。它是辅助梳理工具，也允许直接维护符合契约的规则。旧平台原 Skill 保留。知识引用必须落到真实文件并核验随包权限；规则转换同时记录已验证的 CCPG CLI 能力和人工补料策略，不能只复制 URL 或命令 help。

## 11. 实施阶段

1. 修复现有宿主缺陷：当前聚焦测试 8/12，先解决 Skill 路径、材料误判、确认门禁、工具输出，再继续。
2. 工作区初始化：专用目录、稳定 AGENTS、动态 index、规则部署、状态恢复。
3. 最小规则包：从业务源重建一个代表章节，输出 body/summary/evidence/refs，不复用旧 JSON 假设。
4. 单章真实闭环：内置解析 Skills 和依赖验证，用户材料及知识文件实际读取转 Markdown、按需提炼、原生生成、提交、编辑、AI 修改、确认、导出。
5. 顺序与续跑：三章节依赖、自然顺序、中断恢复、上游 stale。
6. 工作台与飞书发布。
7. 内部聚合打包、安装、公共更新保护和 Desktop 实测。
8. 全案规则编译链完善：合并单元格、跨章依赖、模板/知识授权、CCPG CLI 字段映射、业务冲突确认。

## 12. 验收底线

- 不按导入顺序执行，必须按依赖加自然顺序。
- 专用工作目录外不落任何方案状态。
- 大文件不允许盲目整读；AI 能通过索引找到 summary 和精确原文位置。
- PDF/Office 默认解析 Skills 随插件可用；真实材料与知识原文均完成相关内容解析，覆盖遗漏可见，不以摘要或文件存在冒充读取完成。
- 图片/扫描页通过真实 DSH 多模态调用验收；不安装传统 OCR，未识别数字和单元格有明确缺口，缺少视觉能力或传图失败不得标为成功。
- 每个章节输出完整落盘并进入 index。
- 中断后能从下一个未完成章节继续，已完成成果不丢。
- 飞书真实写入必须显式确认并回读校验。
- 未实测能力不显示可用；未完成验收不标记完成。
