6. **混淆两类材料**：L 列“项目采集材料”只用于当前项目演练；D/E/F/J 是通用输出模板、参考案例、知识和采集模板。两者目录、索引和包边界分离。

8. **用旧平台判断新插件**：开发、验证和完成度只在 `dsh-harness-one` 当前分支判断；旧平台只读参考。

11. **只验证归档、不验证当前 link**：本地 link 安装不会走 registry dependencies 解析；聚合源码目录缺 `node_modules` 时 Desktop import `cron-parser` 失败，整个 Harness One 和方案插件消失。`assemble-one.sh` 必须实体化运行依赖，验收必须看到 Host 日志“8 个子插件已装配”。
12. **用 JSON 字符串比较对象相等**：工具参数可能重建对象或改变键序。准备令牌必须按 JSON 语义深比较，顶层及嵌套重排要通过；篡改、撤销、材料变化仍必须拒绝。不能将疑似传输层机制写成已定位事实。
13. **把材料登记错误推迟到正文提交**：有原始文件不等于已经登记。准备前提示完全未登记的材料，证据错误说明必须使用登记 ID；先登记再准备，不浪费生成后才发现令牌输入变化。
14. **空成果轮询污染诊断**：无 artifactId 的章节不请求正文；真实客户端测试同时覆盖空章零请求、草稿保留和首次成果使用新 snapshot。
15. **把规则编译通过当可连续生成**：输出缺失必须显式处理，内部补充保留来源及待业务验收状态。更新已有项目时要验证旧指纹、保护数据、检查失败回退；测试包不等于完整业务验收。
16. **让业务会话修插件**：运行 Skill 应约束内部错误只尝试适当恢复一次，重复失败停止并交给开发/运维；不能要求业务 Agent 查源码、调私有 HTTP 或绕过工具提交。
17. **把执行顺序当业务章节编号**：order 只决定执行顺序，不代表业务章节编号/层级。页面须分别展示定义和实例状态；有 inputs/资源而没有材料记录时，不得只显示“暂无材料”掩盖输入要求。此项已修复，并在真实 Desktop 核对 8.1–8.5 编号、输入及依赖展示。
18. **所有 PDF 强制视觉读取**：文字提取成功仍统一返回 needs-vision，下一批又遍历所有物理页，导致不必要的渲染、调用和图片上下文。分类与绑定门禁必须同时修正；回归覆盖纯文字、图文同页、扫描、矢量图、批注及只读取视觉缺口。不能只修 Skill 文字。
19. **把多模态能力等同于宿主直传文件**：当前 DSH 会将普通 file 附件投影为路径提示，不能声称 Word/PDF 原始字节已进入模型。复用原生文件能力及官方技能即可，不据此强制图片包装工具。必要图片仍由原生多模态处理；旧视觉工具只作兼容并保留权限、能力、取消和回执校验，不能让业务会话排查源码。
20. **材料子会话退出撤销主章节**：退出钩子不能因为两个会话访问同一目录就恢复整个项目，必须匹配章节 token 的 sessionId。新增真实/宿主回归保护主会话尝试，原生参数冻结后也不得 push 修改 unresolved。
21. **Desktop 原生面板误用浏览器认证与活动会话**：Desktop 的原生连接与浏览器 Cookie 通道不同，直接 fetch 插件私有 HTTP 路由会被正确拒绝；初始错误又被加载空态隐藏，造成一直“读取方案成果”。原生面板读取必须经官方 Typert Remote/Connection，编辑和确认继续走原生命令；保留 HTTP 认证。冷会话用原生 `sessionPersistence.stat` 读取 header/cwd，不要求先发消息，也不加载完整历史。回归需要真实 Gateway 调用、读取不改 state、错误可见及实际 Desktop 加载，不能只验证隔离网页。
22. **一致性检查假定不存在的包路径**：校验应先核对装配脚本与实际目录，不能假定源码有 `licenses/`，或聚合子插件一定包含独立的 `cordis.patch.yml`。r4 首次检查又重复拼接 `dsh-plugins/`；修正实际归档根后重跑，459 个运行文件及聚合 client/index/patch 一致。失败不能略过，也不能把检查脚本路径错当安装失败。
23. **自定义解析技能抢占官方技能**：同名 provider 的 rank 相同会依赖注册顺序，可能让模型加载旧包装而绕过官方能力。内置 Office 直接用官方原文/脚本，rank 601 作后备，宿主 rank 600 优先；回归实际加载来源和 resourceBase。
24. **把生成等待当文件读取慢**：先统计实际工具耗时、请求等待、推演、重试和落盘结果；不能因材料多就增加缓存系统。第三章真实等待主要在模型，整章子智能体无草稿后又重读，write 缺 file_path。默认同一会话、按小节及时保存、断点复用；完整正文以文件提交避免再次生成。保持模板、来源与冲突校验，参数体积改善不能冒称总耗时改善；活动执行不强制迁移规则或重启。
25. **把结构契约留给模型猜**：内置知识是否已登记、附件该用 `outputId` 还是 `id`、当前章能否读取后续知识，都必须由工具 schema 和状态门禁表达。不要靠长提示纠错，也不要让业务会话排查插件源码。2026-10-11 第四章中断即由这三处契约不清叠加图片超窗造成。
26. **为上下文引入第二套管理器**：方案插件不接管压缩、图片卸载或模型重试。材料侧只做一次解析、文档级落盘和精确复用；上下文安全用 DSH 原生 provider 预算与 image-offload。压缩插件冲突是 Desktop 配置事实，不写成方案插件依赖。
27. **把不同章节的待确认事项混成全局队列**：人工审核时无法知道事项属于哪一章，也容易把附件问题误当正文问题。待确认状态必须随章节 artifact 保存，面板按当前章节显示并提供正文定位；最终全文交付只汇总已确认正文，附件仍单独列出。
28. **只在批准前生成交付快照**：用户批准后若正文、附件或清单被修改，继续写入会发布未经确认的内容。创建交付目录后，批准返回时重新校验每个快照文件哈希；变更立即停止并要求重新批准。连接器收到绝对工作目录，避免相对路径在宿主进程中失效。

## 防复发检查

- **普通 Node 测试代替 Desktop 运行验证**：PDF.js 自动 canvas loader 在受限 Electron utility Host 可失败；冷进程回归必须模拟该边界，并用安装路径解析器和实际 Desktop Electron 读原件。依赖必须进入聚合 manifest 及归档原生二进制，不能只在独立包开发 node_modules 可用。
- **Electron Node 模式冒充 utility Host 验收**：`ELECTRON_RUN_AS_NODE=1` 即使使用 Desktop 可执行文件，也没有真实 utility 的环境身份。PDF.js 在 `process.versions.electron` 且 `process.type='utility'` 时跳过 Node worker 默认值；回归须明确覆盖此条件。报告分别标记 Node 模式、身份模拟、真实 Host 和模型续跑，不因换可执行文件就扩大验收结论。
- **图片 fixture 过小造成验收错觉**：1×1 图片只用于字节/传输断言；可见渲染使用实际尺寸测试图，核对 naturalWidth、显示尺寸、编辑保存、ZIP 和窄容器。内联测试脚本未执行不能据页面静态加载判通过；测试初始化放在已加载的 boot 脚本。
- **重复假定聚合布局和小缓冲区**：本轮首次校验再次错把独立子插件 LICENSE/patch 当聚合文件，另一次 tar 目录清单超过默认缓冲区。应先读装配实际布局，对共同运行文件和顶层许可/patch 分开核对，完整大归档清单用足够缓冲区或流式读取；失败后必须重跑并报告实际结果。

- **将原图交付误做成文字解读**：图片附件必须提交原件并直接显示；正文插图保存位置与原图快照，章节和全文下载携带原图。测试覆盖源文件移走后编辑、中文路径编码、原图字节、附件和全文位置；飞书回读位置与原图字节，不把纯文字一致当图文成功。
- **运行截图与隔离测试混称验收**：1x1 PNG 测试只证明图片传输、位置和字节保存，不证明真实业务图可读或模型理解；隔离渲染器检查不能冒称 Desktop、云写或端到端生成通过。

- **目录编号和内部 ID 混入展示**：定义与正文标题合并时按业务 code 去重，附件按同一自然顺序插入。右侧输出使用同一业务 label，不重复拼 ID/编号；浏览器同时核对菜单与输出项。
- **索引冒充原文或加载冒充合规**：知识清单不能冒称已具备原文；原生 Skill 调用证明加载，references read 证明读取，规则遵守与业务质量仍需内容验收。
- **生成包补丁无法复现**：第 7 章补充必须显式源文件编译，覆盖源表空输出、冲突拒绝及 provenance 回归，默认包不能仅靠手工改 manifest。
- **只测预览遗漏编辑**：占位与人工核验小节在富文本编辑均须可见；测试高亮更新/消失及 Markdown 无高亮标签，表格、图片、任务和列表保持。源码编辑的能力边界单独记录。

- 原生成果面板必须在实际容器宽度验证，不能只按浏览器窗口大小验收；窄容器需保证正文可读。
- 内置知识与项目上传材料分别展示，references.inputIds 用于来源核对；显示已内置不等于已解析或已绑定。

- 规则编译测试必须覆盖：泛化规则替换案例规则、标准 frontmatter、目录名等于 `name`、资源相对链接、manifest hash、项目材料不进入通用资源。
- Host 测试必须挂载真实 `@deepseek-ai/dsh-skill` 与 `dsh-skill-filesystem`，确认章节技能来源为 `project-dsh` 且可加载。
- 内部打包前检查归档不包含 `local-data/`、开发过程文档、`.superpowers/` 或公共分发说明。
- 默认规则替换必须记录来源 revision、授权范围和剩余业务 blocker；禁止用模型猜测补定义。
- 核心/Host 回归覆盖令牌顶层及嵌套键序、内容篡改、取消及材料变化；更新失败恢复旧 AGENTS、manifest 和 Skill。
- 客户端回归覆盖空章节不请求成果、草稿保护及首次成果自动同步；真实 Desktop 可见不等于真实模型生成通过。

- 真实 SkillRegistry 必须证明宿主官方 Office 优先及后备原文/资源可加载，不能把本机全局技能当分发内容。旧项目材料指令修复只替换已知段落，保留用户其他指令和所有进度，并覆盖活动章拒绝及保存失败回退。

## 当前纠正结果

2026-10-12 目录分层教训：用户“同一方案目录”和“章节子目录”可以同时成立，最新明确设计覆盖平铺旧决策；开发规则、发布调用、跨范围附件身份、两端链接和原地址更新必须一起修订。目录回归不能用返回同一 token 的假 CLI 验证层级，要检查真实父子成员关系，并覆盖未知创建/移动。安装更新不能直接迁移云文件，用户明确发布时才归位，保留原地址；全文不能重复创建章节附件。

2026-10-12 发布身份教训：不能用全局 revision 或组件内存代表已发布的章节。链接和历史必须从持久回执恢复，云文档身份按章节/全文固定，内容摘要决定复用或更新，revision 仅做并发门禁。回归必须覆盖刷新/重启、其他章节更新、附件改动、正文回退、远端冲突和未知写入；不以重复创建副本补救更新失败。人类明确点击受管原文档更新不能依赖模型轮次批准；Agent 写入批准保持。
