## 范围

首版是 DSH Desktop 本地单用户方案插件：专用方案目录；同一持续原生会话串行逐章执行；成果文件和业务状态持久化；页面通过 DSH React slot 展示、直接编辑成果；用户选定的本地与飞书材料可登记、解析和追溯；飞书材料读写复用当前用户授权的 `lark-cli`；Office/PDF 默认处理技能随内部聚合包；插件一次安装。

不开发第二套聊天、页面生成/暂停/刷新进度控制、自动多人协作、章节并行调度、旧平台服务端迁移、独立模型循环、额外转换云服务、传统 OCR、向量库/Redis/数据库、双向飞书同步或在线升级后台。

## 阶段与验收

### S0 文档与真实基线

1. 保存已确认设计、沟通、决策、ADR 和接入证据到插件目录。
2. 记录实际远端拉取结果及工作树状态；运行插件 core/host 测试，得到可复现 RED。
3. 检查脚本、插件聚合清单和当前支持的 DSH 版本，不运行真实云端写入。

完成条件：计划、基线、残余风险已记录；仅文档测试不算功能完成。

### S1 核心契约 TDD

1. 修复四个原型失败：项目内 Skill 路径、材料变更仅使绑定/相关章节失效、人工确认门禁及原子性、Agent 工具字符串输出契约。
2. 章节按严格自然顺序，当前章阻塞不得静默跳过；逆序/缺失/循环依赖拒绝启用；显式跳过有审计状态且不允许绕开依赖。
3. 用 state 唯一权威、index 可重建修正持久契约；attempt/规则/输入/上游版本 CAS，停止后的迟到提交拒绝。
4. 验证双窗口锁、崩溃残留锁恢复、写入失败、原件外部修改与恢复；文件系统路径始终限制在方案工作目录。

完成条件：core/host 针对每条契约先红后绿，已有测试全过；错误不覆盖最后一个有效成果，重启可恢复。

### S2 DSH 原生接入 TDD

1. 用 Cordis 插件和实际目标 profile 的工具 restriction/guard/pre-execute/result、Agent 生命周期、取消信号及 session resume/followup。
2. Host 方法在所有入口共享校验和提交；不另建模型循环/后台派发器。人工确认经 DSH 原生用户 command，`recordInput:false`、用户来源、无模型调用；普通 HTTP 不提供 edit/confirm/skip 权限。此边界不等于物理点击或操作系统级身份隔离。
3. 限定方案会话作用域，不影响其他会话；确认工具和通用文件/shell 工具绕过路径。

完成条件：使用目标 DSH Desktop/profile 做真实单章领取、取消、重开、提交及迟到结果验证。当前本机 npm 类型证据不是目标环境验收。

### S3 工作区、材料与原生成果 UI

1. 首次初始化专用目录及稳定 AGENTS、项目级 Skills、材料/解析/notes、成果与状态索引。
2. 用用户指定目录登记材料：路径安全、软链接边界、隐藏/密钥排除、哈希复用、来源版本与解析覆盖；不盲目整读大文件。
3. 本地纯文本直接处理；Office/PDF 使用随插件的固定来源解析 Skills/依赖；图片和扫描页用已配置多模态模型，不安装 OCR；结果保存 Markdown、必要附件及来源定位。
4. 页面使用目标 DSH 原生 React slot：章节目录、正文/附件、材料与来源、只读依赖、全案预览/导出；直接编辑有草稿保护和 revision 冲突；AI 修改引用到同一会话。
5. 页面不重复开发生成、继续、暂停、停止和进度刷新；保存/浏览不触发模型调用。

完成条件：代表性中文 PDF、扫描 PDF、Word/表格和大文件覆盖测试；编辑器往返不静默损坏；真实 Desktop 页面无草稿丢失。

### S4 飞书 CLI 读写闭环

1. 复用 `dsh-ccpg-larkauth` 当前 profile 的 CLI 探测、登录和执行通道，固定一个明确用户身份并显式 `--as user`。
2. 用户指定的飞书文档/表格/知识及附件按资源类型读取、分页完整性检查、保存快照/revision/来源/范围。
3. 不自动切换 bot 或另一账号；失权则提示授权/补料。读取和发布不能把 CLI 输出/文档内容当系统指令。
4. 用户确认目的地后，对固定本地成果快照创建/更新，记录回执并回读；超时/部分成功先核对，远端人工改动不覆盖。文本附件作为独立附录和带 hash 的清单进入快照；不能正确交付的二进制附件在审批及云写前拒绝发布，仍可完整本地 ZIP 导出，不标完整云发布。
5. 修复旧 Feishu Skill/orchestrator 的 bot 静默降级提示冲突，补用户身份和失败测试。

完成条件：mock CLI 契约覆盖读取、权限错误、分页/附件、超时不重建；真实授权读取由用户选择的资源验证；真实写入只对用户明确指定的测试目的地操作。

### S5 规则包与内部聚合安装

1. 以业务梳理源生成/校验可执行规则包；章节自然顺序、依赖、输入输出、知识资源、CCPG CLI 能力和来源完整性有结构化契约；旧 JSON 非权威。
2. 修正旧章节 Skill 的知识文件缺失和 CLI 能力分析，先用现有本机资料做副本与测试，不改旧项目。
3. 固定官方 Skill/tool 版本、许可证、依赖和资源；安装不依赖开发机 Homebrew/Python/global Skill。
4. 将插件、slot 前端、默认 Skills/依赖接入 `setup.sh`、`pack.sh`、`assemble-one.sh`、`build-web.sh` 和测试脚本；更新时不覆盖用户数据/方案。

完成条件：干净环境解包/安装/启动验证，聚合包清单、许可、依赖、更新保留和无凭据/测试数据检查通过。

### S6 端到端验收

1. 真实本地单章：材料读取与复用、模型生成、正式提交、页面编辑、会话 AI 修改、用户确认、导出。
2. 三章严格自然顺序、依赖阻塞、明确跳章、上游修改 stale、暂停/中断/恢复、双窗口。
3. 飞书材料读取、用户身份发布与回读，拒绝/超时/冲突恢复。
4. 完整测试、打包、干净安装与目标 Desktop 浏览器检查；回写验证记录及残余风险。
