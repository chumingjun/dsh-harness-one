# 插件技术架构草案

日期：2026-10-09。产品方案及架构复核意见已获用户认可，已授权在 `codex/ccpg-scheme-tdd` 完整实施。接入契约与目标环境仍需验证，设计确认不等于功能完成。

复核入口：[架构与决策复核](ARCHITECTURE-REVIEW-2026-10-09.md)。R1-R8 设计处理原则已获确认，相关决策已同步；原生机制和既有飞书接入的调查证据见 [接入证据](NATIVE-INTEGRATION-EVIDENCE-2026-10-09.md)。设计确认不等于接口已在目标 Desktop 验收。

## 1. 推荐结构与取舍

采用 Cordis 宿主插件、React 工作台、DSH 原生 Agent/Session/Skills 和本地成果文件。同一方案绑定一个原生执行会话，连续执行章节。宿主只校验业务顺序、成果提交和版本，不复制模型循环。Workflow One 同包交付但不作为默认执行依赖；旧 AgentScope/Temporal 服务不迁入。

相对“每章创建新 Agent”，持续会话可避免主动拆散共同历史；相对“所有原件永远保留在提示词”，落盘复用和原生压缩避免为追求缓存而持续扩大请求。哪一种实际更便宜必须看真实使用量，不以架构名称作结论。

## 2. 连续会话与章节边界

撤回此前聊天中的“每章使用独立原生 Agent 上下文”默认建议。流程为：

```text
一个专用方案目录 + 一个持续 DSH 会话
  -> 登记材料，读取并保存解析结果与笔记
  -> 校验并领取下一章
  -> 在当前会话追加本章任务，按需加载本章 Skill
  -> 校验并保存本章成果
  -> 满足确认要求后，在同一会话继续下一章
```

- 会话由当前方案目录定位，能使用已有原生会话时直接绑定；否则只为该方案建立一次。不会每章销毁重建，不另建聊天界面。
- 每章保留独立 attempt、状态和成果版本，用于防止重复提交、乱序和恢复；这些标识不等于独立模型上下文。
- 首选原生持续消息接口；原生上下文读取、压缩和工具历史由 DSH 管理，不在插件里实现手工截断或上下文压缩器。
- Agent 在原生会话中领取、执行、提交章节；不另设后台自动派发循环。业务工具在同一 Host 方法校验和提交，原生钩子负责调用拦截及生命周期接入。
- 必须校验提交、规则版本、所用材料及上游成果，再允许下一章。Agent 空闲或一句“完成”不等于有效提交。
- 用户交互和连续章节执行遵循原生消息顺序；有用户修改、待确认或取消时不得领取下一章。不向忙碌会话另起并行派发，也不阻止当前 Agent 完成本章必要工具调用。
- 开始、继续、重跑和中断的用户入口统一为 DSH 原生会话。立即中断使用原生停止操作；“本章完成后暂停”在原生会话接收后保存暂停意图，由业务领取工具拒绝下一章。不能假定普通聊天消息会即时中止当前请求；忙时不能接收就提示使用原生停止。页面不重复提供运行控制。
- 重开后优先恢复同一原生会话；恢复失败时从持久化索引和有效成果继续，不重新解析全部材料，不承诺保留服务商缓存或恢复模型中间计算。
- 不默认引入子 Agent；后续确需隔离特定任务时另行评估，不能按章节数固定拆会话。

同一方案一次只允许一个有效 attempt。原生取消传播到工具，停止失效后的迟到结果不得接纳；恢复前检查旧执行资格，双窗口保存使用互斥与版本检查，崩溃残留占用须可恢复。工具结束或取消不自动回滚文件与远端副作用，最终提交仍检查 attempt、signal 和输入版本。

## 3. 三种不同的复用

| 对象 | 复用规则 | 谁负责 |
| --- | --- | --- |
| 原始材料、知识转 Markdown/图片/表格 | 相同原件版本、转换规则有效且相关范围覆盖完整时复用；变更或缺页仅更新相关部分 | 插件文件索引与解析 Skill |
| 总结、章节规则与已完成章节 | 已有有效总结不重新提炼；不每章重新编译整包或生成全部旧成果，必要时只读相关片段 | 规则包、成果文件和原生 Skill |
| 模型请求前缀缓存 | 公共指令和工具定义保持稳定，章节任务和新状态后置追加；不为更新进度每章重写系统指令 | DSH 请求组装与模型服务商 |

模型缓存不是保存生成结果。相同会话不保证缓存命中，不同会话也不必然不能命中；具体取决于服务商对请求前缀、模型、缓存有效期等条件的处理。缓存可减少部分重复输入计算，但不会免除新输出生成。

材料“无需重新解析”不等于“以后永远不能再次读取”：上下文压缩后或核对精确数字时，可回读已保存 Markdown 的必要片段；不默认再次读取全部原件并让模型重新转换。解析内容可按 hash 复用，但每次来源登记必须保留各自身份，不能把新来源伪装成旧来源。

不引入 Redis、向量库或专门缓存服务。使用现有材料记录增加来源版本、处理规则版本、结果路径和覆盖状态即可。

2026-10-11 性能实施补充（D-038）：按已声明输出和章内依赖逐节保存原生 Markdown 草稿，必要时记录带来源的简要事实笔记，复用同一会话有效读取。正文完成后以 chapter_submit.bodyPath 读取文件形成成果快照，旧 body 调用继续兼容；既有来源、取消、会话、版本和确认校验不变。没有增加模型派发/压缩/重试循环。参数体积改善已有本地对照，真实生成时间与质量仍需同模型验收；活动方案规则不自动更新，见 [性能记录](PERFORMANCE-2026-10-11.md)。

## 4. 模块和接口

| 模块 | 范围 |
| --- | --- |
| 宿主入口 | 注册工具与本地 API；根据真实 session cwd 定位方案，校验调用范围 |
| 业务核心/文件存储 | 依赖校验、自然排序、领取/提交、确认、编辑、相关下游失效和章节边界恢复 |
| DSH 接入 | 绑定/恢复持续会话、追加任务、观察原生状态、取消；不直接另接模型 API |
| 材料与连接器 | 默认解析 Skill、原件与转换结果登记、CCPG CLI 能力验证和飞书用户身份发布 |
| React 工作台 | 当前方案章节、材料、正文编辑、附件、证据、确认及发布；复用旧页面风格和现有安全预览能力 |
| 打包装配 | 显式接入 assemble/setup/pack/build 清单、默认 Skills 及其依赖、内部更新保护 |

模块是职责边界，不预建每项一个服务或复杂接口层。现有 `lib/index.js`、`lib/core.js` 可按实际复杂度逐步拆分，避免一开始制造大量空文件。前端只消费宿主状态；原生工具和页面操作必须调用同一业务函数。

原生接入使用 Cordis 工具注册、`ctx.tools.restrict()`/同步 `guard()`、异步 `tools/pre-execute`、只观察的 `tools/result` 和 Agent 生命周期。优先最小作用域，不拦截无关会话；依赖 scope 的注册在插件卸载和 Agent 销毁时清理。确认/授权类操作仅由真实用户触发，不提供给 Agent 自行批准。业务提交在方法内完成，不能把结果事件监听器当事务提交层；模型写候选成果，正式成果接纳后才进入页面。通用 shell/文件工具若可绕过提交则需限制或检测外部修改，不能靠 shell 字符串过滤宣称路径隔离。

### 飞书读取与交付接入

复用 `dsh-ccpg-larkauth` 的现有 CLI 安装定位、登录和执行能力，不另建飞书 API/认证系统。当前 profile 内或用户本地安装的 `lark-cli` 均可，但操作固定明确的账号/安装入口，显式 `--as user`，失败不自动换账号或降级 bot。缺少公开 Host service 时仅补最小共享执行入口，不把内部函数存在当作已注册的 service。

用户选定飞书云文档、表格、知识及附件时，经相应 CLI 资源命令获取原文，保存快照、范围、来源、可获得的版本和缺口，再复用材料解析/笔记链路；普通本地文件不经飞书。无权限或用户授权失效时恢复授权或请求补料，不把空结果当成功。

发布固定本地成果快照，用户明确目标和写入意图后用同一用户身份调用 CLI，记录回执并回读正文、表格及必需附件。超时/部分成功先查已有目标，不能盲目重建；远端人工修改不覆盖，不做双向同步。凭据由 CLI/宿主管理，不进入方案文件或模型上下文。旧飞书技能和 orchestrator 中的 bot 自动降级条款属于待修复冲突。

## 4.1 可视化工作台设计

状态：原生 React 成果页已实现，在隔离 DSH 0.2.0-rc.2/sidebar 0.25.0 完成合成样本展示、保存、确认；未在用户现有 Desktop 安装验收。入口绑定当前方案目录和持续会话，不增加项目列表。

优先在宿主原生 React slot 注册成果页面或面板，使用宿主主题、会话 props 和经过检查的 Host 调用入口；撤回默认复用旧 canvasui iframe 的建议。本机官方插件实践明确推荐 slot、不推荐 Host HTML 加 iframe。保留旧页面合适的正文布局和交互，组件在构建时复用，不跨插件导入运行时 Client 值。目标 Desktop 的 slot、主题和会话引用仍须检查，不能自行编造接口或以 DOM 注入代替。

2026-10-10 接入修正（D-035）：原生面板状态、正文和导出通过官方 Typert Remote/Connection，编辑与确认继续通过原生命令。浏览器 Cookie 不作为 Desktop 原生读取前提；原有 HTTP 认证保留。冷会话仅用 `sessionPersistence.stat` 读取 header/cwd，不启动 Agent 或加载完整历史。初始错误必须显示，连接恢复时重新读取。

```text
当前方案名称 / 工作目录 / 成果版本     编辑 / 保存 / 引用到会话 / 导出与发布
章节目录           正文 | 材料与知识 | 依赖 | 全案交付
1. 项目概况        本章标题与版本                   确认/来源抽屉
2. 服务目标        格式工具栏                       需要确认的事项
3. 执行计划        可预览、可编辑的正文              来源与前置章节
...                表格、图片、独立附件入口
```

这是设计布局示意；当前实现的真实验证范围见第 4.1 节状态与验证记录。中间正文占主要空间，右侧详情按需展开；窄窗口将目录、来源调整为适合小屏的布局，不把三个面板挤在一起。保留旧平台的章节目录、文档排版、状态颜色及正文/附件分区，移除项目管理、上传多步向导和独立聊天区。

### 页面内容与交互

| 视图 | 用户看到和可以做的事 |
| --- | --- |
| 正文与附件 | 按章节预览标题、段落、表格、图片；直接编辑正文、保存新版本；独立附件预览/下载，切换已保存版本查看 |
| 材料与知识 | 提供原始文件/目录，查看原件、转换 Markdown、提炼笔记及来源；区分未处理、处理中、已复用、部分解析、缺失/失败；跳到受影响章节 |
| 依赖 | 选中章节后显示前置章节、材料/知识条件和影响的后续章节；点击定位，明确指出缺料、待确认、上游过时；一期用只读列表/关系展示，不做可拖拽流程设计器 |
| 全案交付 | 按业务目录合并预览，列出未完成/过时章节及附件，导出 Markdown 和规定附件；按当前用户身份发布单章或全案飞书文档，保存链接与发布结果 |

页面不建设运行进度控制台、刷新进度按钮或生成/继续/暂停/停止按钮。生成过程和执行指令交给 DSH 原生会话；页面只显示已保存版本、尚未生成、待确认、来源缺失及受影响下游过时等成果状态。用户可以在会话执行期间查看已完成章节，不自动抢走选中章节或滚动位置。

页面仅提供成果关联入口：将当前章 ID、成果版本和选中片段定位引用到同一原生会话并聚焦原生输入区，用户在那里提出 AI 修改意见。页面不另建输入框、聊天记录或 AI 派发队列。若原生引用接口未验证，先展示可复制的精确引用，不能把注入 DOM 模拟操作当可靠接入。原生会话忙时遵循原生交互能力，不偷偷创建新 Agent。手工草稿须先保存或明确放弃，不能无提示地引用旧版。

### 编辑、数据同步与成本

- 默认所见即所得编辑，用户不必编辑 Markdown 语法。优先适配集成仓库已有 Tiptap 编辑器，但先验证 Markdown 往返：标题、列表、表格、图片和相对附件引用不能静默丢失；不支持的复杂内容保持原件或局部只读并说明，不自动转换破坏结构。
- 正文保存使用成果 ID 与预期版本校验，成功后形成新版本；上游修改仅标记相关下游过时。编辑中的草稿与已提交正文分离，切章、关闭面板或后台新版本到来时保护草稿，冲突时保留用户修改供比较，不能被刷新覆盖。
- AI 输出只从已经提交的成果文件进入正式正文区；运行日志和中间对话留在 DSH 会话，未提交内容不能当成正式版本。失败保留原有成功成果。
- 页面打开时读取成果快照，成果提交后优先通过可用宿主事件更新，重新聚焦时核对版本。若宿主没有可用事件，仅在页面可见时低频检查成果 revision，隐藏时停止；不拉取完整执行日志或流式 token，不另建运行监控系统。正在编辑时仅提示有新版本，不覆盖草稿。
- 手工保存、成果确认和浏览依赖不能隐式发起生成或继续；在会话已获授权的连续执行中，是否进入下一章仍由业务门禁和当前会话状态决定。
- 选章、预览、查看依赖和刷新页面只读取本地成果，不触发模型调用、重新解析或重新生成。文档预览能力和模型材料解析能力分别验收。
- 文档展示采用成熟 Markdown 渲染与白名单清洗；模型生成的任意 HTML/脚本不能作为页面直接执行。文件访问使用宿主校验后的相对资源标识，避免前端自行拼接任意本机路径。

### 实现与复用边界

用 React/现有 Vite 构建链、lucide 图标、现有 Markdown 及文档预览组件。旧平台 `web/projects/index.html` 作为布局与交互参考，不直接移植它的 DOM 字符串拼接、身份 API、项目列表和全部样式。集成仓库 `web/src/RichDocEditor.jsx` 与 `dsh-ccpg-document-preview/src/react.jsx` 是候选复用点。

新插件前端放在自己的 `src/`，按工作台、章节正文、材料、依赖和交付视图组织；源码复用通过构建时静态打包，不跨插件做浏览器运行时值导入，不把整个 Workflow One 画布打进去。构建接入 `build-web.sh` 和内部聚合包。产品只运行 DSH 已有宿主进程，无需用户单独启动前端服务器。

建议按顺序验收：代表章节成果展示 -> 正文/表格编辑和草稿保护 -> 材料原件/解析结果/知识引用 -> 成果引用到原生会话并完成修改 -> 全案预览和飞书发布 -> 干净安装与浏览器回归。真实浏览器覆盖切章、窄窗、长标题、宽表格、键盘操作、编辑冲突、断线恢复、发布失败及同一会话执行；验证页面无重复运行控制、仅查看/保存不调用模型、更新不抢焦点不丢稿。演示数据必须标记，不冒充生成结果。

## 5. 状态与一致性

`.ccpg-scheme/state.json` 是章节、材料和成果指针的唯一可写业务状态；`index.json` 是带相同 revision 的可重建 AI 读取视图。稳定运行 AGENTS.md 告诉模型读取索引，不动态追加整段执行历史。

正文和附件先完整落盘，再原子更新 state 指针；索引滞后时据 state 重建。使用 revision 防止两个页面或旧任务覆盖新成果。不能声称多个独立 JSON 文件的重命名就是跨文件事务。失败暂存文件不作为已完成成果，确认绑定具体成果版本。

执行顺序来自明确章节 order 与依赖，标题和导入数组顺序都不充当身份。依赖不存在/有环应拒绝启动；依赖顺序与业务顺序冲突须可见，不让模型私自重排。无关材料新增不应让当前章失效。

默认严格自然顺序，当前章阻塞则停；用户明确跳过时仅允许运行不依赖该章的后续章，保留缺章状态。缺失依赖、有环、重复章节和逆序依赖在规则启用前拒绝。workspace 保存身份和格式版本，publications 保存回执，均不形成第二个章节状态源；DSH 会话日志仍是对话历史权威。正文、规定附件、来源和确认条件分别校验，文件存在不等于成果合格。

项目固定激活的规则包版本；安装更新只提供新默认包，旧项目暂停后明确激活兼容新版，检查依赖并仅标记相关成果，不执行中热替换。材料限用户指定范围、检查软链接与敏感文件；材料是数据，不执行宏/其中的指令。CCPG CLI 优先获取不代表数据自动优先，来源冲突需保留口径并确认。不额外上传第三方转换服务；本地应用不意味着使用远程模型时数据不出本机。

## 6. 默认技能的独立交付
