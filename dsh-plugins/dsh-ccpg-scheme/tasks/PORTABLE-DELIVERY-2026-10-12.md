# 标准插件与可移植交付

用户要求：无需内部源码，通过 DSH 对话安装内部包；不依赖某个操作系统的原生组件。禁止本轮安装到用户 Desktop、重启运行中的会话、提交、推送或公共发布。

## 实施范围

1. 保留标准 Cordis 入口、bundle patch、client 和 DSH 原生工具/技能，不修改宿主。
2. 去掉方案运行依赖中的系统 Office 和原生 canvas。PDF 使用随包 WASM，Office 使用纯 JS 结构读取；扫描/复杂内容仍以原文件交给原生多模态核对。
3. 保留 Word 图片位置、正文/附件分离、解析缓存、来源校验和资源限制。旧 Office 排版转图不作为跨平台承诺，返回原生文档处理指引，不假装已转换。
4. 内部交付使用标准 npm `.tgz`，不包含开发机 node_modules 或绝对路径；依赖在目标机安装。附带跨平台 Node 安装入口及自然语言安装说明，明确当前 profile，不改端口/模型/凭据。
5. 安装前校验 Node/DSH、包摘要及宿主兼容范围；安装失败不声称成功。飞书/CCPG 用户登录单独完成，不带开发机凭据。
6. 测试先行：依赖边界、原生库不可用的真实解析/Word 导出、隔离安装替身、包内容及全仓回归。实际 Windows/Linux/Desktop 首装没有测试设备时明确未验收。

## 真实宿主入口补充

安装后的真实 HTTP 检查发现成果浏览器入口返回 400：将 Node `IncomingMessage` 展开后转交 `connection.authorizeIndex`，丢失了原型 getter `headers`，因此原生鉴权缺少 Host/Cookie。原单测用字面量请求对象，未覆盖真实请求结构。两个鉴权分支显式保留 `method` 和 `headers`，不修改宿主认证或放宽权限；`IncomingMessage` 回归先失败再通过，Host 17/17 通过。修复同步进入 r15 包，最终归档和真实启动结果以下方收尾记录为准。

验证复盘：启动检查先读实际路由定义，成果页路径是 `/ccpg-scheme/results`，不是 `/ccpg-scheme/`；HTTP 验收先完成原生 token/cookie 交换。控制台没有子插件日志不代表未挂载，应核对原生客户端和实际端点。临时宿主按自身进程组停止，避免后台写入与清理竞争。

收尾验证：修复后全仓 `npm test` 通过；最终 ZIP 重新核对 5 个交付文件、593 个插件运行文件、两份归档 SHA-256，确认包含当前鉴权修复，且不含开发/废弃/原生二进制内容。隔离真实 DSH 安装及启动通过，聚合客户端与 sidebar 客户端实际挂载，`/wf1/`、`/ccpg-scheme/results`、`/ccpg-scheme/browser.js` 返回 200，未登录的成果页访问返回 401。测试宿主与临时目录已清理。

最终 ZIP：`dist-release/dsh-harness-one-0.11.4-internal.portable.r15.zip`，40,987,866 bytes，SHA-256 `df8c27811e549b3129a1d5229b3fa19935b1cb81341cf24ef698cd76c9bae082`。这仍是内部验证包，不代表 Desktop GUI、多平台设备、真实模型或飞书云交付全部验收。
