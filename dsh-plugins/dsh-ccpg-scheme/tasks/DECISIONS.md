## D-001 本地单用户 DSH Desktop 插件

- 状态：Accepted，设计已确认，实现与验收未完成。
- 决策：首版运行在每个用户自己的 DSH Desktop 中，插件随内部聚合包安装。
- 原因：用户明确选择本地使用，不需要多人共享服务和后台运营能力。
- 影响：优先复用 DSH 原生 Session、Agent、Skills 和文件能力；不迁移 AgentScope Worker、Temporal、数据库或旧平台服务。

## D-002 旧平台只读，旧 JSON/Skill 仅作参考

- 状态：Accepted，设计已确认，实现与验收未完成。
- 决策：`ccpg-ai-scheme-platform` 不修改；旧章节 JSON、旧 Skill 和旧材料只用于结构参考、回归对照或本机验证。
- 原因：旧产物不一定符合当前插件需求，且用户要求保留原有内容。
- 影响：规则 authority 必须来自当前业务梳理源、真实知识、用户材料和验证过的 CCPG CLI 能力。

## D-003 每个方案使用独立工作目录

- 状态：Accepted，设计已确认，实现与验收未完成。
- 决策：首次使用创建或选择一个专用完整方案目录，并将其作为 DSH 原生会话 cwd。
- 原因：避免方案状态、材料和成果混入其他项目或外层仓库。
- 影响：目录包含稳定 `AGENTS.md`、`.dsh/skills`、材料、成果和 `.ccpg-scheme` 索引；未初始化时不得静默写外层目录。

## D-004 轻量材料登记与按需提炼

- 状态：Accepted，设计已确认，实现与验收未完成。
- 决策：材料只做登记、hash 去重、解析状态和来源记录；总结/归纳由章节 Skill 按需完成，精确引用保存到 notes。
- 原因：用户希望避免重复读取和 token 浪费，同时不建设过重的自研上下文系统。
- 影响：上下文读取和压缩由 DSH 原生 Agent 管理；规则要求先看元数据/目录/局部样例，禁止盲目整读大文件。

## D-005 `.ccpg-scheme/index.json` 保存动态过程索引

- 状态：Accepted，设计已确认，实现与验收未完成。
- 决策：运行时 `AGENTS.md` 保持稳定；`state.json` 是唯一可写业务状态源，保存材料、章节状态和成果指针；`index.json` 是带同一 revision、从 state 重建的 AI 读取视图。
- 原因：动态执行记录不应不断膨胀指令文件，也不应让 AI 每次扫描整个工作区。
- 影响：先保存完整成果再切换 state 指针，索引滞后时重建；workspace 记录工作区身份和格式版本，publications 记录发布回执，不另建章节状态源。DSH 会话日志仍是原生对话历史权威；插件文件不取代它。

## D-006 首版按依赖和自然顺序串行执行

- 状态：Accepted，设计已确认，实现与验收未完成。
- 决策：先校验依赖，默认严格按业务显式自然顺序逐章串行。当前章阻塞就说明原因，不自动跳章；用户明确要求跳过后，只允许执行不依赖被跳过章节的后续章，并保留缺章标记。
- 原因：业务逻辑有明确先后，用户暂不需要并发复杂度。
- 影响：文件遍历和导入顺序不能影响执行；缺失依赖、有环、重复章节及逆序依赖在启用前拒绝并指出冲突，不由模型静默重排。

## D-007 按章节边界恢复

- 状态：Accepted，设计已确认，实现与验收未完成。
- 决策：已提交章节保留；优先恢复同一原生会话，中断章节重新准备并从未完成章节继续，不承诺恢复模型中间计算。会话恢复失败时仍复用落盘材料与成果。
- 原因：DSH 原生会话可以继续交互，但不应假装能恢复任意脚本的中间位置。
- 影响：同一方案只有一个有效章节 attempt，停止后失效的 attempt 不能再提交；取消信号传播到工具，恢复前核对旧执行资格。状态和成果持久化；双窗口写入互斥、版本检查、崩溃残留占用恢复和幂等提交必须验证，但不建设并行调度器。

## D-008 CCPG CLI 按验证结果取数

- 状态：Accepted，设计已确认，实现与验收未完成。
- 决策：只有项目级能力、权限、字段、期间和口径验证通过时才优先用 `ccpg-cli`；否则请求人工材料。
- 原因：help 或资产名称不能证明真实数据可用。
- 影响：查询结果和元数据写入 `materials/fetched`；失败不伪造成功，不无限重试。优先获取不是事实优先级；与人工材料冲突时保留来源、期间、单位和口径，必要时请求用户确认，不能静默覆盖。

## D-009 飞书读取与发布使用当前用户身份

- 状态：Accepted，设计已确认，实现与验收未完成。
- 决策：飞书材料读取、文档创建、更新与回读统一调用用户本地或当前 DSH profile 已安装并授权的官方 `lark-cli`，复用 `dsh-ccpg-larkauth` 登录集成；显式选择用户身份，不另建认证或 Feishu API 客户端。
- 原因：用户要求第一期完成飞书交付，同时不希望插件内置密钥或隐式写入。
- 影响：本地 Markdown 是主版本；用户指定的飞书文档、表格和知识文件读取后登记原文快照、来源、范围和可获得的版本信息。创建/更新需明确目的地和写入意图，发布固定成果快照，记录回执并回读校验；超时不明先核对，不能盲目重建；远端人工变更不静默覆盖，不做双向同步。详见 D-018。

## D-010 页面只围绕当前方案成果

- 状态：Accepted，设计已确认，实现与验收未完成。
- 决策：保留旧平台合适的页面风格及正文编辑、附件、证据、确认、材料和依赖状态视图；不做项目列表、知识后台、工作流设计画布或第二套聊天。
- 原因：用户打开插件要处理当前方案，运行交互可直接使用 DSH。
- 影响：开始、继续、重跑、暂停和中断的用户入口统一放在原生会话，页面只引用成果供会话内修改。页面不开发运行按钮或刷新进度控制；未核实的预览能力不能宣称可用，飞书内嵌不支持时展示本地预览并打开链接。

## D-011 统一安装与兼容 Skill 替换

- 状态：Accepted，设计已确认，实现与验收未完成。
- 决策：独立开发业务代码，装配到 dsh-harness-one 内部包一次安装。内置方案规则、章节 Skills、运行 AGENTS.md 模板、依赖及允许分发的资源。
- 原因：用户无需重复安装业务插件；业务同事仍能独立改进章节 Skill。
- 影响：项目固定已激活规则包版本，安装更新只提供新默认包；已有项目暂停后明确激活兼容新版，检查依赖并仅标记受影响成果，失败保留旧版，不在执行中热替换。交付使用联合验收的版本组合，不追随各组件 latest；不建设在线升级/通用迁移平台，卸载不删除用户方案目录。

## D-012 规则梳理辅助与知识文件完整性

- 状态：Accepted，设计已确认，实现与验收未完成。
- 决策：在新目录修订开发侧 authoring Skill；它是可选生产工具，不强制沿用旧 JSON。编译前分析 CCPG CLI 支持范围，并核实知识引用指向真实文件。
- 原因：旧产物曾遗漏知识原文和能力分析，不能仅复制提示词或保存 URL。
- 影响：资源需记录相对路径、版本、来源、hash 和完整度；局部缺失明确阻断相关章节。可读不等于可分发，旧知识仅允许本机使用时不随安装包外发。先保证代表章节闭环，再完善全案编译。

## D-013 完整成果与有限失效范围

- 状态：Accepted，设计已确认，实现与验收未完成。
- 决策：每章保存正文、总结、附件、证据、确认项、上下游引用；原件与 notes 分别保存。修改生成新成果版本并更新索引。
- 原因：用户回来时应能定位已完成内容，后续章节应能追溯用过的材料和上游结果。
- 影响：确认绑定具体版本及真实用户操作；模型不能自行批准。正文、规定附件、来源和未决确认项分别校验，文件存在或 Agent 空闲不代表完成。上游修改只标记受影响下游 stale，外部文件修改不得伪装成有效提交；编辑草稿和不可无损往返的复杂内容不得被刷新或转换破坏。

## D-014 PDF/Office 解析作为默认内置能力

- 状态：Accepted，具体选型与实现待验证。
- 依据：2026-10-09 用户要求一期必须解读材料和相关知识，并将主流 PDF/Word 解析技能作为默认 Skill 随插件交付。
- 决策：采用内置解析 Skills + 成熟文件解析工具 + 用户配置的多模态模型，由 DSH 原生 Agent 执行。用户后续明确图片/扫描页只走多模态模型，不安装传统 OCR，也不以 OCR 自动降级。必要的页面渲染用于传图，不负责文字识别；统一安装处理其必要依赖，技能部署到专用工作区。
- 原因：用户要直接提供原始材料；不能因文件是 PDF/Office 就延期或要求先手工整理。Skill 本身不等于可运行的工具和模型能力。
- 影响：替代设计稿旧有的 Office/PDF 分期表述。相关内容转换为 Markdown，保留原件、必要图片/表格附件、源定位和解析覆盖情况；notes 只作另存的提炼。已解析的同版材料可复用，扫描件或依赖缺失不得假成功；最终来源及分发方式待核实。
- 验收补充：验证实际 DSH 视觉输入链路，模型配置本身不作为通过证据；模糊数字不得猜填，无法识别的部分保留待核对项。不新增 OCR 安装包、语言包或服务。

## D-015 持续会话与跨章节复用

- 状态：Accepted，接入方式待验证。
- 依据：用户否定每章新建独立上下文，要求尽量利用模型缓存，避免重复解析材料和章节。
- 决策：一个方案持续原生会话，逐章追加任务；章节独立 attempt/成果用于业务状态，不等于独立上下文。解析、摘要与已有成果落盘后复用，相关变化才更新。
- 原因：不主动破坏共同历史，避免重复准备；同时不依赖短期模型缓存来保存业务成果。
- 影响：公共指令/工具定义保持稳定，动态章节消息后置，压缩交由 DSH。不承诺相同会话一定命中缓存，也不为追求命中率发送无用历史。精确回读允许且不同于全量重新转换；验证总输入输出、重复转换次数及可用 usage 指标。

## D-016 会话负责执行，页面负责成果

- 状态：Accepted，接入细节待实测。
- 依据：用户指出旧页面生成/刷新进度等交互存在问题，希望执行优先通过 DSH 会话，页面侧重成果展示与修改。
- 决策：去掉页面运行控制台，仅保留成果预览、编辑保存、确认、来源/依赖、引用到当前会话、导出发布。成果版本自动同步；不做第二套聊天或请求队列。
- 影响：可视化范围缩小，但持久化、依赖顺序、重复提交保护和章节边界恢复仍必需。原生立即停止和章末暂停须区分，不把聊天里的暂停意图当作已经生效。查看/保存不触发新模型任务，后台新成果不能覆盖草稿。

## D-017 原生插件钩子与业务提交共同保障约束

- 状态：Accepted，接口已在本机官方包查到，目标 Desktop/profile 待验证。
- 决策：复用 Cordis 插件、`ctx.tools.restrict()`、`ctx.tools.guard()`、`tools/pre-execute`、`tools/result` 及 Agent 生命周期/取消信号；业务状态仍在同一 Host 方法中校验并提交，不依赖事后事件替代事务。Agent 在原生会话领取和提交章节，不另建后台派发循环。人工确认是用户专属操作，原生审批入口需验证调用来源。
- 原因：DSH 提供通用运行/扩展机制；章节顺序、材料版本和成果完整性由插件定义，两者配合而非复制原生运行时。
- 影响：guard 同步拒绝，异步检查在执行前或业务方法中完成，最终提交时仍重新检查版本和取消状态；钩子不自动撤销已经完成的文件/远端副作用。限制只作用于当前方案作用域，不改变其他会话。通用 shell/文件写入若不受约束，必须检测外部修改，不能声称 guard 是操作系统级沙箱；不得以正则过滤 shell 命令假装形成路径隔离。优先使用原生 React slot 承载成果页，撤回默认 iframe 方案。

## D-018 飞书 CLI 复用与用户身份不降级

- 状态：Accepted，实际 CLI 命令、授权作用域及目标环境待验收。
- 决策：复用 DSH 已有飞书账号登录和 CLI 执行能力，标准命令 `lark-cli`，显式 `--as user`；当前 profile 与本地已有 CLI 都可作为入口，但一次方案操作使用明确、固定的安装与账号，不因某一入口失败而切换另一个账号。飞书文档、表格及附件按各自资源类型读取，分页/附件遗漏要登记，不只读标题或链接。
- 影响：凭据由 CLI/宿主管理，不进方案目录或模型上下文。缺登录、过期或缺权限时恢复用户授权或请求补料，绝不自动降级 `--as bot`；账号切换后重新核对授权与来源。登录成功不等于拥有任意文档访问权。旧 `feishu-cli` 技能与 orchestrator 提示中的 bot 降级条款列为后续修复，不在本轮改代码或触发登录/云端写入。

## D-019 材料安全与最小交付验收

- 状态：Accepted，来自用户同意的 R5/R8。
- 决策：材料处理限定用户指定范围，检查软链接越界和敏感配置；原件是数据，不执行其中的宏、命令或越权指令。原文转换保留覆盖范围、来源和缺口，单次提取/传图采用合理大小与时间上限，不建设上下文预算系统。复用宿主权限，不额外上传到转换服务；本地应用使用远程模型时不宣称离线处理。
- 影响：验证中文 Office/PDF/图片、复杂表格无损编辑范围、目标操作系统/架构、干净安装与已有安装更新。无法无损编辑的部分保留原件或局部只读；读取权限不等于资源可随安装包分发。

## 2026-10-10 实施细化与未完成边界

- 开发、验证和完成度判断统一在 `dsh-harness-one`；旧平台不作为当前验收依据。章节业务处理内容编入对应生成 Skill；方案 AGENTS 维护共用约束，manifest 维护可校验的结构。
- 飞书主表 D/E/F/J 的资源分别登记为输出模板、参考案例、知识原文和填写模板；L 列“项目采集材料”独立下载到仓库根目录 `local-data/ccpg-scheme/project-materials/`。该目录忽略 Git，并在插件装配范围外，不能进入内部或公共安装包。
- 同一资源在通用模板和项目采集列中出现时，保留两种用途记录；填写模板指针不是项目已采集事实，参考案例也不是当前项目事实。演练时根据来源索引选择真实项目材料，成果另存专用方案工作目录。
- 下载原件和解析正文只证明获取/解析状态，不证明分发许可、视觉内容核对或生成验收；未核实的分发权保持未知，不擅自将其改成允许。

- 原生人工 channel 使用 DSH 用户 command：页面编辑/确认/skip 不启动模型、不向 Agent 提供确认工具；普通 HTTP 拒绝这些修改。复用宿主认证，不承诺操作系统隔离或物理点击证明。
- 图片/扫描结果保存必须经过当前会话成功 `read_image` 凭据、源文件和图片 hash、完整覆盖检查；`material_complete_visual` 保存 Markdown 与未决项。这不证明识别质量，真实模型验收仍必需。
- 内部包固定 sidebar 0.25.0 与 DSH 0.2.0-rc.2 组合。Node 最低 22.19.0，来源于内置转换器要求；不是无条件追逐所有 latest。
- 飞书文本附件进入固定发布附录和 hash 清单；没有验证过的二进制云交付能力时，审批前拒绝发布，不能遗漏附件却声称完整成功。完整二进制云交付仍是未完成需求。
- 最终限定复审指出跨轮取消资格漏洞，已增加 A/B/C 三轮测试并重绑当前轮信号。停止后旧 token 必须拒绝，不因新轮信号重获资格。
- 旧飞书 bot 降级冲突提示已经修复；历史条目中的“本轮不改代码”仅描述当时调查，不再定义当前实施范围。
