# CCPG Scheme DSH 插件开发规则

本文件只约束 `dsh-ccpg-scheme` 业务插件的开发、验证、装配和文档维护。它不是用户运行方案工作目录中部署的 `AGENTS.md`；后者由插件在初始化专用方案工作目录时生成，内容和生命周期以 `tasks/DESIGN-2026-10-09.md` 为准。

## 权威来源

- 用户最新明确指令优先。
- 当前产品设计以 `tasks/DESIGN-2026-10-09.md` 为准。
- 当前执行入口是 `tasks/ACTIVE-PLAN.md`。
- 决策、沟通和验证记录分别维护在 `tasks/DECISIONS.md`、`tasks/COMMUNICATION-LOG.md` 和 `tasks/PROCESS.md`。
- 旧平台 `/Users/linbiqiu/源码/ccpg-ai-scheme-platform` 只读；旧 JSON、旧 Skill 和旧产物只能作为参考或本机测试样本。
- 当前开发、验证和完成状态核对只在 `dsh-harness-one` 进行；不得使用旧平台的实现、计划或验证结果判断本插件是否完成。

## 工作边界

- 最终插件随 `/Users/linbiqiu/new-api-test/dsh-harness-one` 的内部聚合包安装。
- 遵循集成仓库 `/Users/linbiqiu/new-api-test/dsh-harness-one/AGENTS.md` 的插件、构建和验证约定。
- 使用 DSH 原生 Session、Agent、Skills、文件能力和已验证的宿主接口；不修改 DSH Runtime，不迁移旧平台服务端。

## 产品与数据约定

- 标准产品名是 **CCPG CLI**，命令是 `ccpg-cli`。本机版本只作为实测记录，不代表兼容范围或最新版本。
- CCPG CLI 只有在项目、权限、字段、期间和口径都验证通过时才自动取数；否则明确请求用户补充材料。
- 飞书材料读取与发布复用用户本地或当前 DSH profile 的官方 `lark-cli` 和 `dsh-ccpg-larkauth` 登录，明确固定安装入口/账号并显式 `--as user`；失败不切 bot 或另一账号，不另建认证/API 客户端。读取保存快照、来源及范围；创建/更新前明确目的地和写入意图，状态不明先核对。凭据不进入源码、日志、规则包、方案目录或安装包。
- 默认规则、章节 Skill、展示定义和必要资源随内部包分发；用户材料、成果、凭据和运行状态不打包。
- 一期必须内置 PDF、Word/Office 解析 Skills，并通过统一安装流程提供或检查实际工具依赖。用户材料及相关知识原文都要读取转换为可追溯 Markdown 和必要附件，不能把摘要当原文解析结果，也不能以分期为由省略此能力。
- 图片、扫描页及复杂版面使用用户配置的多模态模型，不安装传统 OCR 或将其作为自动降级。按需提取/渲染页面用于模型输入，验证 DSH 实际传图链路；模糊数字和无法识别内容保留缺口，不猜补。
- 普通文字 PDF/Office 直接提取并完成；图文或含其他部件的可读文档标记 `needs-review`，使用原生文件能力及官方技能按文档核对，不强制逐图/新子会话；扫描或无可靠文本来源才标记 `needs-vision`，按实际需要复用原生多模态。`material_complete` 保存文档级 Markdown、source hash、核对说明和缺口，一原件一材料，未读业务信息不得冒称完整。旧视觉工具只兼容已有进度。内置 Office 官方原文/资源作为 rank 601 后备，宿主 rank 600 优先。工具返回成功不等于真实模型语义验收。
- 本地 Markdown 是主版本，飞书文档是明确发布后的副本；发布后需要回读校验并记录结果。
- 同一方案复用一个当前用户飞书总目录；每章首次发布时在其下创建并持久复用“业务编号 章节标题”子目录，本章正文与附件同放；全文正文放总目录，全文发布复用章节附件，不另建副本。目录回执按方案保存并沿用旧发布记录。用户点击发布/整理目录时，已登记的历史正文与附件归入章节子目录并保留原 token/链接；安装和只读加载不移动云文件，不删除历史文件。目录不可访问、位置冲突或创建/移动结果不明时停止写入，不另建目录绕过。以 D-052 替代 D-050 的平铺规则。
- 安装依赖以原生能力、代码注入与干净 Host 验证为准，不能把本机曾调用的记忆、压缩、图片或自动续跑社区插件全部加入默认包；核查依据见 `tasks/PLUGIN-DEPENDENCY-AUDIT-2026-10-12.md`。
- 用户要求创建或点击飞书转换即为创建授权，不再二次确认，也不要求模型轮次内批准。明确点击“更新飞书文档”授权更新本范围已登记的原文档；Agent 发起更新及任意目标覆盖仍保留原生批准。账号、权限、目的地、版本、快照完整性、取消、幂等与回读检查保持。
- 飞书发布按章节或全文持久关联原文档，页面从回执恢复链接和历史；全局 revision、标题或无内容变化的成果版本不触发重复创建。更新原正文与匹配附件，先校验远端基准；未知写入、远端编辑及附件身份/类型冲突不得另建副本绕过。旧云文档不自动删除，安装不迁移业务 state。
- 方案执行异常必须写入专用目录 `.ccpg-scheme/diagnostics.jsonl`，字段遵循 ADR-0007；不得记录正文、材料内容、原始参数、token 或凭据。未提供显式运维 endpoint 与用户同意前不自动上云。
- 运行交互优先且统一使用 DSH 原生会话；页面不开发重复的生成、继续、暂停、中断和刷新进度控制。页面专注成果展示、直接编辑、确认、来源/依赖核对及交付，AI 修改通过成果引用进入同一会话。保留自动成果同步和草稿保护，不因去掉按钮而取消持久状态与业务校验。
- 对话入口按用户意图触发方案场景，不要求固定命令或页面按钮；材料可来自会话附件、本地文件/目录、飞书文档/表格、飞书材料清单或已验证 CCPG CLI 数据。必填完整性由插件准备门禁强制校验，模型只转述缺口。
- 用户明确提供当前方案的飞书表格材料清单时，插件以当前用户 CLI 自动抓取清单中的全部有效资源，在方案目录保存可读命名原件和清单索引，不逐份询问。仅用来说明需求或输入形式的示例链接，不代表读取/下载授权；开发验证用模拟清单，不访问该示例。下载与解析状态分开，缺权限/缺链接不得声称采集完整。
- CCPG CLI 缺失或未配置时，使用全局 `ccpg-scheme` Skill 内的官方初始化 reference 和 `ccpg_cli_status` / `ccpg_cli_setup` 工具。Linux 支持一键安装、强制更新和 `config init`；跨平台或网络失败不猜命令，转为明确人工/运维步骤。

## 开发纪律

- 使用 `apply_patch` 做手工编辑；保留用户已有修改，不使用破坏性 Git 命令。
- 不提交、不推送、不发布公共 npm，不写入未确认的线上飞书目的地。
- 业务定义、输入输出、依赖、证据、确认和成果必须用可验证文件契约表达，不能只藏在页面或提示词中。
- 每章的业务处理指令、材料要求、前置成果和输出模板引用编入该章生成 `SKILL.md`；方案 `AGENTS.md` 只维护全案共用约束，manifest 保留对应可校验结构。不得仅复制通用生成提示或将用户方案正文当作 Skill。
- 章节技能必须符合 DSH 原生文件发现格式：专用方案目录 `.dsh/skills/<kebab-name>/SKILL.md`，frontmatter 必填 `name`、`description`，目录名与 `name` 一致，资源放在该技能目录并用相对链接引用。不得发明私有技能清单替代 `ctx.skills`/`dsh-skill-filesystem` 协议。
- 业务表是项目案例，不得把项目名、历史合同日期、“已采集”文件和源表行号直接写成通用规则；先维护 `authoring/chapter-rules/*.md` 泛化源再编译。资源文件的用户可见名称用来源标题，hash 仅用于身份与完整性校验。修改技能链路后必须查看 [纠偏复盘](tasks/RETRO-2026-10-10.md) 并运行对应防复发检查。
- 首版严格自然顺序串行，当前章阻塞不自动跳章；用户明确跳过时只允许无相关依赖的后续章。有环、缺失、重复及逆序依赖拒绝启用。一次一个有效 attempt，停止后迟到结果不得提交，双窗口写入需版本检查；断点恢复按章节边界处理。
- 复用 DSH 原生插件工具管线与生命周期，业务方法负责最终提交校验，事件只观察；人工确认不能交给 Agent 自行批准。state 是业务状态权威，index 是派生，DSH 日志是会话历史权威；通用 shell/文件写入不受限时检测外部修改，不宣称 OS 级隔离。
- 原生会话退出只恢复该会话拥有的有效章节尝试；材料子会话退出不得撤销主会话章节。DSH 的原生工具参数不可变，额外缺口先复制再整理，不能原地修改。
- 项目固定规则版本，暂停后明确激活兼容新版，安装更新不改旧项目；CCPG CLI 优先取数不代表冲突事实自动优先。成果页优先原生 React slot，旧页面只复用合适组件和风格；复杂内容不得静默转换丢失。
- 同一方案默认复用持续原生会话，不每章新建上下文。复用已解析材料、笔记和有效章节成果；必要时精确回读，不重复全量处理。保持公共指令稳定，缓存及压缩由 DSH/模型服务商负责，成本验收看总使用量和重复工作，不仅看缓存命中率。
- 章节按 Outputs 和章内依赖逐节成稿并用原生文件工具即时保存，不整章派发后重新全量阅读；事实笔记保留来源、期间、单位与冲突，不替代原文。已保存完整正文优先以 bodyPath 提交，提交快照和全部既有门禁保持；真实速度以模型端到端对照验收，不能拿参数缩小比例当总耗时改善。活动项目不替换规则指纹或重启 Host。
- 新增或修改行为必须有对应测试和验证记录；未通过实际验证不得声称完成。
- 准备令牌按 JSON 语义比较，两处提交门禁保持一致；不得放松取消、会话、输入版本和内容校验。材料先登记再准备，业务会话不承担源码排错或私有 HTTP 绕过。
- 页面展示业务 `code`，执行排序使用 `order`；定义、材料绑定和成果状态分别核对。未生成不请求正文，不把“暂无材料”当作没有输入或知识定义的证据。
- Desktop 原生面板的读取通过官方 Typert Remote/Connection，编辑和确认通过原生命令；不能依赖浏览器 Cookie 或为使页面可用而放宽 HTTP 认证。冷会话用原生 `sessionPersistence.stat` 读取 header/cwd，不先启动模型或读取全量历史。初始读取失败必须显示错误，不能永久停在加载空态。
- 文档和过程记录与代码同等重要，任何改变设计的技术结论都要更新 ADR 或当前规格。
