# ADR-0003：轻量材料登记与动态索引

## 状态

原轻量材料方向已确认；下述“直接维护 index”条款由 [ADR-0005](0005-native-hooks-and-user-feishu-cli.md) 替代：state 为权威，index 为派生。历史正文保留供追溯，不作为现行状态契约。

## 日期

2026-10-09

## 背景

材料可能很大，重复整读会浪费上下文并增加失败概率；用户同时要求能够保存总结、精确来源和执行过程。

## 决策

材料进入工作区后记录路径、类型、大小、hash、解析状态和说明。按需生成的 note 保存结论和精确来源位置。动态章节指针、依赖状态和发布记录写入 `.ccpg-scheme/index.json`，运行时 `AGENTS.md` 保持稳定。

## 结果

章节优先读取 notes 和上游 summary，需要事实时才回读原文片段。上下文大小和压缩交给 DSH 原生 Agent；插件不建设第二套上下文预算系统，也不做语义去重。

## 2026-10-09 范围补充

用户已明确一期必须处理 PDF/Office 材料及相关知识文件，并默认内置解析 Skills。轻量登记不意味着省略原文转换：DSH Agent 按技能使用成熟文件工具，图片、扫描页及复杂版面直接由用户配置的多模态模型解读；不安装传统 OCR。必要时仅渲染页面后传图，验证实际视觉链路，分批保存 Markdown、图片/表格附件和来源定位到 `materials/parsed/`。notes 为另存提炼，不能替代原文解析。默认技能和必要依赖纳入统一安装验收；具体选型待验证，见 D-014。此补充不引入独立解析服务或自研上下文管理。

## 2026-10-10 纠偏

以 D-037 为准：有内嵌图片不代表必须逐图核验或新建子会话。原生文件能力和官方 Office 技能读取整份文档，必要图像才使用多模态；插件保存文档级结果与明确缺口，不选择另一套模型循环。纯文本 `complete`，可读图文 `needs-review`，扫描/无可靠文本 `needs-vision`；未读业务内容不自动视为完成。官方 Office 技能原文/资源内置为后备，宿主官方技能优先。
