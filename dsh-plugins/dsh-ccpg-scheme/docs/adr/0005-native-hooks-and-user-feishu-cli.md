# ADR-0005：原生钩子、统一状态与用户级飞书 CLI

## 状态

Accepted：2026-10-09 用户确认架构复核意见并要求同步决策；实现与目标 Desktop/profile 验收未完成。本记录替代 ADR-0003 的直接维护 index 表述和 ADR-0004 的 ready 集合自动跳章策略；补充 ADR-0001，不迁移旧运行时。

## 日期

2026-10-09

## 背景

用户要求原生会话运行、页面专注成果、严格章节顺序和低成本复用，并明确飞书材料读取与发布均使用用户已安装或 DSH 集成的飞书 CLI。原草案将“是否有原生钩子”与“目标版本是否兼容”混为一谈，且状态权威、跳章与规则替换语义存在歧义。

## 决策

1. 使用 DSH Cordis 插件、原生工具 restriction/guard/pre-execute/result 与 Agent 生命周期及取消信号。业务 Host 方法负责顺序、attempt、版本和完整性校验与提交；结果事件只观察，不代替事务。不复制模型循环，不另建后台派发器。人工确认是用户专属操作。
2. 默认严格自然顺序，当前章阻塞不自动跳过；用户明确跳过时才运行不依赖该章的后续章。循环、缺失、重复及逆序依赖拒绝启用。一次只有一个有效 attempt，取消后旧尝试不得提交；保存防双窗口冲突。
3. state 是唯一业务状态源，index 是带 revision 的派生索引；先完整落盘再切换指针，索引滞后可重建。DSH 会话日志仍负责对话历史。版本校验、文件外部改动检测不等于 OS 安全沙箱。
4. 项目固定激活规则版本，安装升级不自动改变旧项目。暂停后明确切换兼容规则，只标记相关成果；材料取数优先级不替代事实冲突判断，原件只作数据，限制读取范围及敏感文件。
5. 飞书读取和发布统一复用 `lark-cli` 与 `dsh-ccpg-larkauth`。显式 user 身份，失败不降级 bot 或切换账号，不另建认证/API 客户端。读取保存来源快照和范围；发布固定快照，明确授权目的地，回读校验，部分成功/超时不盲目重复创建。
6. 成果页面优先原生 React slot，保留旧页面合适风格而非 iframe 嵌入整站。复杂表格不静默降级；安装使用联合验收版本组合，干净环境验证，不借用开发机工具。

## 证据

具体声明、代码位置和版本边界见 [原生接入证据](../../tasks/NATIVE-INTEGRATION-EVIDENCE-2026-10-09.md)。本机官方包已经提供扩展机制，待核对目标 Desktop/profile 的真实挂载及语义，不再把“是否有 hook”作为架构未知项。

## 结果

2026-10-10 实施补充：人工修改使用原生用户 command，不经模型；停止资格随当前轮重新绑定。D-037 默认文档读取复用原生文件能力、官方 Office/PDF 技能与必要多模态，整件 Markdown 经 `material_complete` 保存来源、核对说明及缺口，不强制指定图片工具或子会话。成功 `read_image` 凭据加内容/覆盖校验仅保留在旧视觉进度兼容工具，不作为默认门禁。文本附件通过固定发布附录/hash 清单交付，尚无验证过的二进制 CLI 上传/回读契约时审批前拒绝。具体通过与未验收项以 [最终验证](../../tasks/VERIFICATION-2026-10-10.md) 为准。

保持薄插件与原生运行，避免重复建设调度、认证和上下文系统。增加的是必要的业务提交/版本约束与最小兼容验证，不新增重型服务。原决策阶段未改代码；后续已实现当前用户 CLI 的失败关闭契约，真实飞书发布仍需单独验收。
