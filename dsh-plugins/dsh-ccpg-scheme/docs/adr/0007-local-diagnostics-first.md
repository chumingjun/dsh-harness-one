# ADR-0007：先本地结构化诊断，再接线上运维通道

## 状态

Accepted：2026-10-10 用户要求收集方案生成过程中的错误以便运维介入，同时明确不要过度设计。

## 背景

插件在用户各自 DSH Desktop 本地运行。没有统一服务端时，直接自动上云会引入 endpoint、身份、隐私授权、重试和数据归属问题，还可能为了次要目标拖慢主链路。

## 决策

1. 每个专用方案目录保存 `.ccpg-scheme/diagnostics.jsonl`。原生工具、人工 command 和页面 HTTP API 的异常统一追加一条结构化记录。
2. 记录字段限定为时间、级别、操作入口、项目/章节标识、错误码、脱敏错误消息、插件版本和规则版本；不记录正文、材料内容、原始参数、token、凭据或飞书内容。
3. 单文件超过 1MB 时轮转为 `diagnostics.jsonl.1`，只保留当前与上一份，避免撑爆用户目录。
4. `project_status` 与页面状态接口返回最近 20 条，用户或运维可以直接定位；支持时可直接收集该 JSONL。
5. 后续提供线上通道时，只批量上传该标准 JSONL，并要求用户显式同意与运维 endpoint 配置；不在本期自动上报。

## 结果

运维拿到用户方案目录或诊断文件即可判断插件版本、规则版本、失败操作和错误原因；线上上报可作为后续同格式转发器接入，不改变本地运行主链路。
